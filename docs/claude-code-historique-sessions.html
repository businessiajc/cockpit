Où Claude Code garde l'historique de vos sessions sous Windows

Mis à jour le 11 novembre 2026. Ce guide décrit ce qu'on observe sur un poste Windows 11 ; il n'est pas une documentation officielle d'Anthropic.

Quand Claude Code travaille, le terminal défile vite. Une trace de chaque session reste pourtant sur votre disque. La retrouver permet de relire ce qui s'est passé, sans rien relancer.

1. Où sont les fichiers

Sous Windows, le dossier se trouve dans votre profil utilisateur : %USERPROFILE%\.claude\projects. Collez ce chemin dans la barre d'adresse de l'Explorateur de fichiers. Chaque projet sur lequel vous avez lancé Claude Code y a un sous-dossier, dont le nom reprend le chemin du projet avec des tirets à la place des séparateurs.

2. Ce que contient chaque fichier

Chaque session est un fichier .jsonl : une ligne de texte JSON par événement (message, appel d'outil, résultat). Ce sont des fichiers texte, ouvrables avec le Bloc-notes. Le plus récent par date de modification correspond à la session la plus récente.

3. Précautions avant d'ouvrir

  • Lisez, ne modifiez pas. Ouvrez une copie si vous voulez expérimenter.
  • Ne les partagez pas telles quelles. Ces fichiers peuvent contenir des chemins personnels, des extraits de code, et parfois des secrets que l'agent a lus (clés, mots de passe d'un fichier de configuration). Relisez avant tout envoi.
  • Le format n'est pas documenté officiellement : il peut changer d'une version à l'autre.

4. Les lire sans parcourir des milliers de lignes

Un fichier de session fait vite plusieurs mégaoctets, et les lignes sont illisibles pour un débutant. Deux approches :

  • Un éditeur avec recherche (Bloc-notes, VS Code) : cherchez un mot de votre demande pour retrouver l'endroit qui vous intéresse.
  • Un outil qui traduit le fichier en phrases simples. Cockpit, que nous développons, fait cela en local : il lit ce dossier, affiche l'état de la session en français et ne modifie rien. Il est gratuit pendant la phase de lancement, mais il est jeune : testé sur un seul poste Windows 11, et son exécutable n'est pas signé (Windows peut donc afficher un avertissement).

Limites de ce guide

Je n'ai vérifié ces chemins que sur un poste Windows 11. Sous macOS ou Linux, le dossier de base est différent et je ne l'ai pas contrôlé ici.
